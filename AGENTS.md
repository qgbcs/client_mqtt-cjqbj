# Client MQTT Agent Guide

## Scope
- Work only inside `client_mqtt/`.
- Never edit the workspace-level `multi_mqtt/` or `Xime_rpc/` directories.
- `app/src/main/python/multi_mqtt/` is the only project-local copy of the library and is generated by `debug_build_secexp.sh`; do not hand-edit it.
- The source library is supplied through `MULTI_MQTT_SOURCE` (default: the sibling `../multi_mqtt` directory).

## Product boundaries
- MQTT carries RPC control code and small JSON metadata only.
- Remote browsing runs `os.walk` and `os.stat` on the target device through RPC.
- File bytes and photos use the target-side `aliyun_git` upload plus client-side HTTP download.
- Photo capture must keep JPEG bytes in memory and must not write a photo file on the target device.
- Never print Aliyun tokens, private keys, or generated RPC secrets.

## Development rules
- Keep UI, Python bridge, RPC code generation, and transport adapters separate.
- New runtime features must follow `FEATURE_DEVELOPMENT.md`; do not add feature-specific Compose code to the main activity.
- Use explicit JSON for RPC results; do not depend on pretty-printed Python repr for new protocols.
- Bound recursive scans with a configured page size and return `has_more` and `next_offset`.
- Reject path traversal, symlink escape, and unbounded recursion.
- Add or update a focused test before widening a change.
- Update `PROGRESS.md` after each verifiable milestone and update `PROTOCOL.md` when a wire contract changes.

5. Record unavailable device tests in `PROGRESS.md`; do not claim them as complete.
